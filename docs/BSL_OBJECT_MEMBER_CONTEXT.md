# BSL: реквизиты объектов и методы менеджеров из расширений

## Причина

`ContextLinksCachedScopeProvider` добавляет имена типов и глобальных свойств выбранных проектов.
При разрешении одного имени собственный тип имеет приоритет. Кроме того, `ПолучитьОбъект()`
может возвращать уже разрешенный тип основной конфигурации: повторного поиска его имени
в составной области видимости не происходит.

Реквизиты объекта и экспортные методы менеджера EDT ищет в `ContextDef` конкретного типа.
Доступность имени общего модуля не доказывает доступность членов одноименного объекта.
Исправление QL-таблиц для конструктора запроса также не меняет BSL-типы.

## Исправление

`ContextLinksDynamicFeatureAccessComputer` подключен через существующий `ContextLinksBslRuntimeModule`.
В момент поиска члена или построения подсказки `ContextLinksMemberTypes` добавляет в список
кандидатов одноименные типы непосредственно выбранных проектов. Проект-потребитель определяется
по переданному BSL-ресурсу, а не по владельцу типа, полученного из основной конфигурации.

Используются штатные `TypeItem` и `ContextDef`, включая ссылки на контексты модулей. Разрешение
методов, проверка окружений, типов и переход к исходнику остаются в штатной реализации EDT.
Категории `CatalogObject`, `CatalogRef`, `CatalogManager` сопоставляются отдельно.

- Базовые и донорские модели не изменяются и не копируются.
- Нет обхода всех метаданных, принудительного прогрева и пересборки доноров.
- Донорские области видимости берутся из существующего BSL-кеша при каждом обращении.
- Транзитивные связи не обходятся. Настройка отключения BSL-контекста учитывается.
- Основная конфигурация не получает контекст выбранных чужих расширений.
- Если EDT вообще не определила тип выражения, этот механизм не придумывает его.

## Проверки

После сборки Maven:

```powershell
./tools/test-bsl-member-context.ps1 -EdtHome '<путь к установленной EDT>'
./tools/test-query-context.ps1 -EdtHome '<путь к установленной EDT>'
```

Регрессии используют реальные классы EDT для подсказки и разрешения членов. Проверяются реквизит
расширения у уже разрешенного типа, несколько расширений, экспортный метод менеджера в ссылочном
контексте модуля, ограничения окружений, разрешение прокси, отсутствие изменений исходных моделей
и исключение типов, не выбранных в настройке контекста.

Ручная проверка в EDT:

1. Подключить расширение в настройках контекста проекта внешних обработок/отчетов.
2. Установить собранный ZIP как локальный архив сайта обновления и перезапустить EDT.
3. Проверить `Договор = ВыборкаДоговоров.Ссылка.ПолучитьОбъект();`, затем подсказку
   и разрешение `Договор.ММ_Проект`.
4. Проверить экспортную процедуру расширения через `Справочники.ДоговорыКонтрагентов`.
5. Проверить базовые реквизиты, общие модули и конструктор запроса.
