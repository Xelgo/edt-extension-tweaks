# Зависание Git-фильтра: issue #3

## Оценка диагностики

Предложение исправить фильтр обосновано исходным кодом. `ViewerFilter.select()` синхронно вызывал
`Git.status().call()`, а возраст снимка отсчитывался до получения статуса. Расчёт дольше 1500 мс делал
снимок устаревшим ещё до следующего элемента дерева и приводил к повторению полного обхода репозитория.
Даже перенос отметки времени на конец расчёта оставил бы Git status в UI-потоке и последующие паузы
после истечения TTL. Поэтому одного изменения TTL недостаточно.

В JFace из поставки EDT подтверждено, что `StructuredViewer.addFilter()` и `removeFilter()` сами
вызывают `refresh()`. Дополнительные `refresh()` удалены. `expandToLevel(3)` тоже удалён: он принудительно
создавал дополнительные узлы и менял выбранное пользователем раскрытие дерева.

Данные issue не подтверждают причинную связь с MCP-EDT: в приведённом стеке его классов нет, а второй
пользователь описал тот же дефект без установленного MCP. Поэтому отключение другого плагина не является
необходимой частью исправления.

## Реализация

- Одна сериализованная Eclipse Job на активный Навигатор вычисляет готовый неизменяемый снимок.
  Проекты одного репозитория используют один Git status за проход, ключом служит Git directory.
- `select()` не разрешает EGit mapping, не обходит файловую систему и не запускает Git status.
  Он сопоставляет location ресурса с уже известными корнями рабочих деревьев и индексом путей.
- Индекс содержит изменённые пути и их предков. Проверка узла зависит от глубины его пути,
  а не от общего количества изменённых файлов.
- Первичная загрузка оставляет дерево доступным; готовый снимок применяется через `Display.asyncExec()`.
  Последующие загрузки оставляют предыдущий снимок до замены.
- Повторное нажатие кнопки и закрытие Навигатора отменяют задачу и снимают слушатели. Номер запроса
  запрещает применять устаревший результат, включая уже поставленный в очередь UI callback.
- События CONTENT, добавления/удаления ресурсов и изменения проектов, а также события Git index,
  refs, working tree и смены repository mapping запрашивают обновление с задержкой 500 мс.
  Изменения только маркеров ошибок не запускают Git status.
- Ошибка чтения отдельного репозитория записывается в журнал; объекты этого репозитория остаются
  видимыми. Неизвестное состояние не подменяется успешно вычисленным пустым списком изменений.

## Проверки и границы

Автотесты запускаются на настоящих библиотеках EDT/JGit. Тест с искусственной задержкой статуса
1700 мс проверяет отдельный рабочий поток, единственный статус для трёх ссылок на один репозиторий
и 30 000 вызовов фильтра без повторного статуса. Другие тесты проверяют отмену, закрытие после
постановки результата в UI-очередь, повторный запрос во время расчёта, последовательность задач,
вложенные репозитории, пути с пробелами и настоящие staged/unstaged/deleted/untracked/ignored файлы.
Отдельный SWT-тест создаёт скрытое дерево на 5000 файлов и проверяет, что UI-таймер продолжает
обрабатываться до завершения фонового расчёта, а применение и снятие фильтра дают ожидаемые узлы.

Тест воспроизводит условие, которое ломало старый TTL, но не является замером конкретного
пользовательского workspace. Сохранение файла вне EDT станет видно после получения события Git
или обновления ресурсов workspace, например штатной командой Refresh. Принудительный периодический
обход репозиториев не добавлен.
